## 项目简介 V1.10.23

`ZhiLianAuto` 是一个基于 **FastAPI** 的智联招聘（Web 端）自动化工具，提供前端页面 + 后端接口，用于：

- 上传/管理 cookies（用于请求智联站点）
- 自动回复、二次会话
- 保存简历并上传到 AnyHelper/AnyJob 相关接口

---

## 运行环境

- **Python**:  3.12
- **系统**: Windows 10/11

## 安装依赖

在项目根目录执行：

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -U pip
.venv\Scripts\pip install -r requirements.txt
```

## 启动后端（同时提供 API + 静态前端）

```bash
.venv\Scripts\python main.py
```

- 默认监听：`http://127.0.0.1:11451/`
- `main.py` 会尝试挂载静态目录：`frontend/dist`
  - 注意：本仓库的 `.gitignore` 忽略了 `dist/`，因此你本地可能没有 `frontend/dist`，这会导致前端页面无法正常显示，但 **API 仍可用**。请事先build一次前端再一键启动后端+前端。

## 目录说明（重要）

所有运行时文件统一落在项目根目录的 `save/` 下（由 `backend/core/utils/path_util.py` 决定）：

- `save/cookies/`：上传的 cookies 文件
- `save/session/`：上传的会话策略文件
- `save/excel/`：导出的 Excel（如有）
- `save/debug_im/`：调试用 IM HTML（开启.env中的环境变量开关才会写）

## API 使用说明（用于调试/脚本调用）

### 高潜上传的学校与专业

新增高潜人才请求向 `add_screening_resume.php` 传入独立的 `school`、`major` 字段。
从智联原始教育经历中选择最高学历对应的同一组学校和专业，支持学历名称及智联编码；同学历保留首条，缺失字段留空，不从其他经历拼接。
仅一条有效经历但学历未知时保留该条，多条均无法识别学历时两个字段留空。

该规则覆盖独立高潜上传、策略/Excel 首次沟通及全自动调用的对应流程，不增加 AI 请求。
现有 `schoolName`、`major` 身份属性、SmartKeywords、金币和正式人才入库逻辑保持不变；已有高潜更新不回填或覆盖教育字段。

### cookies 上传与列表

- **上传 cookies**
  - `POST /api/search_condition/cookiesFile`
  - multipart/form-data
  - 文件字段可能是 `file` 或 `zhilian-cookie-txt`（后端做了兼容）
- **获取 cookies 列表**
  - `GET /api/search_condition/cookiesList`

### 会话/保存简历相关

- **启动自动回复**
  - `POST /api/conversation/start_auto_reply`
  - Body（JSON）：

```json
{
  "position_id": "123456",
  "cookies_file_name_list": ["ChromeCookie-智联-xxx.txt"],
  "reply_mode": "all"
}
```

- **停止自动回复**
  - `POST /api/conversation/stop_auto_reply`
- **启动二次会话**
  - `POST /api/conversation/start_second_conversation`
  - Body 与 `start_auto_reply` 相同
- **保存简历（会触发抓取 IM HTML + 解析历史消息 + 上传）**
  - `POST /api/conversation/start_save_resume`
  - Body（JSON）：

```json
{
  "reply_mode": "all",
  "start_time": "2026-04-01 00:00:00",
  "end_time": "2026-04-08 00:00:00",
  "position_id": "123456",
  "cookies_file_name_list": ["ChromeCookie-智联-xxx.txt"]
}
```

## ChatBot 接口与返回格式

本节记录的是 **当前 `ZhiLianAuto` 源码实际使用的接口契约**。修改 AnyHelper 后台 Bot Prompt 时，必须保持对应返回格式，否则可能导致筛选结果为空、字段提取失败、消息被误发或流程异常。

### 调用协议

所有 Bot 统一调用：

```text
POST https://model.example.invalid/api/completions/quora.php
Content-Type: application/x-www-form-urlencoded

prompt=<输入内容>
chatbotID=<Bot 配置标识>
```

HTTP 响应必须是 JSON，且至少包含：

```json
{
  "choices": [
    {
      "message": {
        "content": "Bot 实际返回文本"
      }
    }
  ]
}
```

代码固定读取 `choices[0].message.content`。`chatbotID` 只是 AnyHelper 后台 Bot 配置标识，源码不能据此确认底层使用的是 GPT、Claude、DeepSeek 或其他模型。

### 当前 Bot 清单

Bot 配置位于 `backend/core/config/chatBotApiConfig.py`：

| 用途 | 枚举名 | Chatbot ID |
|---|---|---|
| 首次沟通候选人预筛 | `GET_FIRST_CONVERSATION_SIMPLE_CHECK` | `__TALENTMATCH_MODEL_28__` |
| 快速搜索策略 | `GET_AI_FAST_STRATEGY` | `__TALENTMATCH_MODEL_25__` |
| 随机搜索策略 | `GET_AI_RANDOM_STRATEGY` | `__TALENTMATCH_MODEL_26__` |
| 深匹搜索策略 | `GET_AI_DEEP_STRATEGY` | `__TALENTMATCH_MODEL_27__` |
| 第一次匹配判断 | `GET_FIRST_CHECK` | `__TALENTMATCH_MODEL_05__` |
| 二次事实复核 | `GET_FACT_CHECK` | `__TALENTMATCH_MODEL_06__` |
| 清洗简历 | `GET_CLEAN_RESUME` | `__TALENTMATCH_MODEL_08__` |
| 简历摘要 | `GET_SIMPLE_RESUME` | `__TALENTMATCH_MODEL_19__` |
| 简历翻译 | `RESUME_TRANSLATOR` | `__TALENTMATCH_MODEL_30__` |
| 聊天文本标签 | `GET_CHAT_TAGS` | `__TALENTMATCH_MODEL_29__` |

| 二次联系 | `SECOND_CONTACT_MSG_GEN` | `__TALENTMATCH_MODEL_23__` |

### 首次沟通候选人预筛

必须只返回通过预筛的原始 `resumeK`，使用英文逗号分隔：

```text
resumeK值1,resumeK值2,resumeK值3
```

消费端直接执行 `resumeK_str.split(',')` 并按完全相等匹配。不要增加引号、字段名、解释、Markdown 或 JSON 数组；无结果时返回空字符串。

### 搜索策略

搜索策略按行解析，字段名与中文全角冒号 `：` 都是接口契约。不要把中文冒号改成英文冒号；多个城市或行业名称使用半角空格分隔；没有有效内容的行使用固定文本 `无有效信息`。

快速策略：

```text
学历要求：本科
年龄要求：25-40
工作年限：3-10
薪资要求：20-40
工作地点：上海 北京
```

随机策略：

```text
简历描述关键词：新能源 海外销售
职位关键词：海外销售经理
公司名称关键词：新能源 光伏
```

深匹策略支持以下固定字段：

```text
搜索词-产品：
搜索词-核心技能：
搜索词-次要技能：
专业关键词：
岗位-具体名称：
岗位-核心词：
岗位-大类名称：
公司名-企业类型：
公司名-细分行业精准词：
当前行业：
公司名-竞争对手：
搜索词-客户名：
搜索词-市场名：
工作城市：
附近城市：
```

> 已知问题：当前快速策略的年龄上限解析写成了 `.stirp()`，不是 `.strip()`。即使 Bot 返回正确的 `年龄要求：25-40`，执行到该分支仍可能抛出 `AttributeError`；这是消费端代码问题，不能通过修改 Prompt 规避。

### 匹配判断与事实复核

第一次匹配判断按以下顺序识别全文中的关键词：

1. `非常匹配`
2. `不匹配`
3. `匹配`

该分支不单独识别 `不确定`，因此建议只返回以上三种结论，并让结论出现在开头，例如：

```text
非常匹配，原因：候选人的核心经历符合岗位要求……
```

二次事实复核按 `不匹配`、`不确定`、`非常匹配` 的顺序识别，其他内容默认按 `匹配` 处理。后续备注还会执行 `fact_check_comment.split('，')[3:]`，因此必须使用中文逗号并至少保留四段：

```text
是，判断合理，确实非常匹配，原因：候选人的核心经历符合岗位要求……
```

```text
否，不合理，判断结果应为不匹配，原因：候选人缺少必要经验……
```

不要使用英文逗号替代中文逗号，也不要在最终结论前放置相反状态词。

### 清洗简历、摘要与翻译

清洗简历返回 Markdown，其中以下四个字段名称和粗体标记必须原样保留：

```markdown
**期待薪资**：20K-30K/月
**居住地**：上海
**优势标签**：新能源出海、渠道建设、团队管理

**推荐语**：
候选人的核心优势……

---
```

代码使用的正则为：

```regex
\*\*推荐语\*\*[:：]?\s*([\s\S]*?)(?:\n---|\n##|$)
\*\*期待薪资\*\*[:：]?\s*(.+)
\*\*居住地\*\*[:：]?\s*(.+)
\*\*优势标签\*\*[:：]?\s*(.+)
```

其中 `**推荐语**` 在当前上传流程中会直接取第一个匹配结果，缺失时可能抛出 `IndexError`。简历摘要没有结构化解析要求，但应返回非空纯文本。简历翻译必须返回 Markdown，并保留独立一行的 `---` 分隔符；代码会按该分隔符拆分后，在第一段追加手机号和微信号。

### 聊天标签与薪资清洗

`GET_CHAT_TAGS` 的结果会不经解析直接保存到 `chat_tags`。Bot 应只返回标签文本，不要返回 JSON、编号列表或解释。当前约定标签为：

```text
地点不考虑
薪资不符合
岗位不匹配
不感兴趣
未读消息
已读不回
有意向沟通
被联系过了
不看机会
```

`GET_TAG_BY_CHAT_HISTORY` 的结果会直接保存，并尝试通过 `int(str(status_tags).strip())` 参与金币规则计算，因此必须只返回整数，例如 `256`，不要返回 `标签：256`、`256（强意向）` 或 JSON。当前金币规则明确使用的标签 ID 包括：

| 标签 ID | 业务含义 |
|---:|---|
| `104` | 在职急寻 |
| `105` | 在职看机会 |
| `107` | 离职 |
| `109` | 需再联系 |
| `110` | 不跳槽 |
| `256` | 强意向 |

`GET_CLEAN_SALARY` 的返回值会直接保存为薪资字段，只返回一个清洗后的薪资字符串，例如：

```text
20K-30K/月
```

不要增加字段名、说明、多个备选结果或 JSON。

### 自动回复与二次联系

自动回复和二次联系的最终结果都会整段发送给候选人，必须返回单条可直接发送的纯文本。不要返回“建议回复如下”等说明、多个方案、JSON、Markdown 代码块或模型思考过程。

自动回复存在特殊控制词 `不回复`：

- 需要跳过发送时，最安全的返回是单独一行 `不回复`；
- 正常回复中不得出现 `不回复` 子串，即使上下文是“无需不回复”或“并非不回复”，代码仍会标记已读并跳过发送。

二次联系会连续调用两次 `SECOND_CONTACT_MSG_GEN`：第一轮输出会作为第二轮输入，第二轮输出才会发送。因此两轮输出都应是干净纯文本，不要在第一轮返回 JSON 或元说明。
