# 猎聘到智联字典映射说明

## 1. 文档目的

本文说明猎聘搜索策略转换为智联搜索策略时使用的字典来源、生成流程、映射规则、字段对应关系、安全策略和维护方法。

本次改造重点解决以下问题：

- 猎聘未填写职位关键词时，智联错误生成 `JOB=123`。
- 猎聘 `nowJobTitleArr`（当前职位）未转换到智联 `currentJobTypes`。
- 猎聘 `wantJobTitleArr`（期望职位）曾被误写入智联行业字段。
- 猎聘当前城市和期望城市曾被反向写入智联。
- 猎聘“统招不限”曾被强制转换成智联“统招”。
- 猎聘 `filterChat: false` 曾仍然生成智联“未聊过”过滤。

## 3. 生成文件

| 文件 | 用途 |
| --- | --- |
| `data/liepin_industry_code.json` | 猎聘官方行业原始字典的本地 JSON 版本 |
| `data/liepin_position_code.json` | 猎聘官方职位原始字典的本地 JSON 版本 |
| `data/liepin_zhilian_industry_map.json` | 猎聘行业到智联行业的安全映射 |
| `data/liepin_zhilian_position_map.json` | 猎聘职位到智联职位的安全映射 |
| `tools/build-recruiting-platform-maps.js` | 下载、解析、比对并重新生成上述文件 |

映射文件的基本结构如下：

```json
{
  "source": "猎聘官方字典地址",
  "generatedAt": "生成时间",
  "summary": {
    "exact_unique": 0,
    "exact_parent": 0,
    "manual_override": 0,
    "ambiguous": 0,
    "unmapped": 0
  },
  "mappings": {
    "猎聘编码": {
      "sourceName": "猎聘名称",
      "sourceParentCode": "猎聘父级编码",
      "status": "映射状态",
      "targets": [
        {
          "value": "智联编码",
          "label": "智联名称",
          "path": ["智联一级分类", "智联二级分类"]
        }
      ]
    }
  }
}
```

## 4. 映射状态和安全规则

| 状态 | 含义 | 转换行为 |
| --- | --- | --- |
| `manual_override` | 经人工确认的一对一或一对多映射 | 直接使用 |
| `exact_unique` | 名称相同，且智联只有一个候选项 | 直接使用 |
| `exact_parent` | 名称相同但智联存在重名，通过父级路径得到唯一结果 | 直接使用 |
| `ambiguous` | 名称相同，但父级仍不能唯一消歧 | 跳过并输出控制台警告 |
| `unmapped` | 未找到可靠对应项 | 跳过并输出控制台警告 |

运行时不会把 `ambiguous` 或 `unmapped` 条件映射到任意“最接近”的选项。宁可少一个筛选条件，也不生成错误搜索条件。

## 5. 职位映射

猎聘职位字段与智联字段的对应关系：

| 猎聘字段 | 含义 | 智联字段 |
| --- | --- | --- |
| `jobName` | 自由文本职位关键词 | `jobKW` |
| `nowJobTitleArr` | 当前职位分类 | `currentJobTypes` |
| `wantJobTitleArr` | 期望职位分类 | `expectedJobTypes` |

`jobName` 为空时，`jobKW` 保持空字符串，不生成智联 `JOB` 文本条件。

示例：

```json
{
  "code": "N0038",
  "name": "人力资源"
}
```

转换结果：

```json
{
  "value": 2000014,
  "label": "人力资源"
}
```

智联路径为：

```text
人事/行政/党群 > 人力资源
```

## 6. 行业映射

猎聘行业字段与智联字段的对应关系：

| 猎聘字段 | 含义 | 智联字段 |
| --- | --- | --- |
| `industryArr` | 当前行业 | `currentIndustries` |
| `wantIndustryArr` | 期望行业 | `expectedIndustries` |

行业允许一对多映射。例如猎聘一级行业“消费品”覆盖多个智联行业。

当前测试策略中的行业映射如下：

| 猎聘 | 猎聘编码 | 智联目标 |
| --- | --- | --- |
| 消费品 | `H05` | 批发/零售/贸易 `700000000` |
| 消费品 | `H05` | 快速消费品 `700010000` |
| 消费品 | `H05` | 耐用消费品 `700030000` |
| 医疗健康 | `H06` | 生物医药/医疗 `1300000000` |
| 汽车 | `H07` | 汽车 `1600000000` |

转换时会按智联编码去重。

## 8. 示例策略的预期转换

对于本次用于验证的猎聘策略：

- 关键词：RPO 供应商
- 当前城市：上海、北京、江苏、浙江、广东
- 当前职位：人力资源
- 当前行业：消费品、医疗健康、汽车
- 工作年限：5 年以上
- 年龄上限：45 岁
- 活跃度：近 6 个月
- 期望年薪：20 万以上
- 统招要求：不限
- 未聊过过滤：关闭

关键转换结果应满足：

```json
{
  "jobKW": "",
  "currentJobTypes": [
    {
      "value": 2000014,
      "label": "人力资源"
    }
  ],
  "expectedJobTypes": [],
  "currentCityIds": [
    { "label": "上海", "value": 538 },
    { "label": "北京", "value": 530 },
    { "label": "江苏", "value": 539 },
    { "label": "浙江", "value": 540 },
    { "label": "广东", "value": 548 }
  ],
  "expectedCityIds": [],
  "schoolNatures": [],
  "filteringChatted": false
}
```

转换结果中不应出现：

```json
{
  "key": "JOB",
  "values": "123"
}
```

## 9. 更新字典

在项目根目录执行：

```powershell
node tools\build-recruiting-platform-maps.js
```

生成工具会：

1. 下载当前配置的猎聘官方职位和行业字典。
2. 解析猎聘编码、名称、父级编码和层级关系。
3. 递归展开本地智联职位和行业字典。
4. 优先应用人工映射。
5. 执行唯一同名匹配。
6. 对智联重名项使用父级路径消歧。
7. 将仍有歧义或无法匹配的项目标记为不可自动转换。
8. 重写四份猎聘字典和映射 JSON。

猎聘更新静态资源版本后，需要同步更新工具顶部的 `sources` 地址，再重新运行。

## 10. 人工维护映射

行业人工映射维护在：

```js
const industryOverrides = {
  "猎聘行业编码": ["智联行业编码"]
};
```

职位人工映射维护在：

```js
const positionOverrides = {
  "猎聘职位编码": ["智联职位编码"]
};
```

人工映射支持一个猎聘分类对应多个智联分类。修改后必须重新运行生成工具，并检查映射文件中的：

- `summary`
- 对应编码的 `status`
- `targets`
- `path`

不要直接长期维护生成后的 JSON；重新生成时手工修改会被覆盖。

运行全部回归测试：

当前回归测试覆盖：

- 空职位不会生成 `123`。

- 消费品、医疗健康、汽车的一对多行业映射。
- 当前城市与期望城市不反向。

- `filterChat: false` 保持关闭。

当前共 34 项测试通过。

## 12. 已知限制

- 714 个猎聘职位尚无可靠智联对应项。
- 76 个职位存在无法通过父级唯一消歧的重名情况。
- 72 个猎聘行业尚未映射。
- 当前策略是“安全跳过”，不会进行模糊语义猜测。
- 猎聘或智联更新分类体系后，需要重新生成并复核覆盖率。
- 对业务上必须保留的未映射条件，应先人工确认，再写入 `positionOverrides` 或 `industryOverrides`。
